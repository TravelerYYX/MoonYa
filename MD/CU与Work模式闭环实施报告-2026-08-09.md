# MoonYa CU 与 Work 模式闭环实施报告

日期：2026-08-09

## 结论

本次已完成从“发送请求”到“唯一可持久终态”的闭环改造。Work/CU 任务不再依赖原始 SSE 连接存活；页面断开、切换视图或重新连接后，后台工作进程仍继续执行，客户端按 `run_id + client_message_id + after_seq` 补发事件。

真实 HTTP 断线测试已验证：首次连接在 `run.started` 后主动中断，独立工作进程仍完成 MoonYa 到 Search Agent 的真实交接。本次外部搜索服务返回失败，但系统正确收敛为 `agent.failed -> run.failed`，恢复连接收到唯一终态，没有悬空任务。

## 已实施

- 修复 CU Function Schema 在 `parameters` 为 `stdClass` 时的真实崩溃。
- 新增数据库执行作业、SSE 事件日志和本地工具请求三层持久化。
- 新增独立 PHP CLI 工作进程，包含原子领取、心跳、重放、停止和崩溃收敛。
- 本地 Windows 工具中继改为数据库票据，使用一次性 Token 验证和幂等回执，重连不重复点击或输入。
- 增加 `completed / partial / failed / cancelled` 终态一致性，并修复“中途可恢复错误覆盖最终 Run 状态”问题。
- Work 和 CU 现在分别发送 `run.completed`、`run.failed` 或 `run.cancelled`，不再把失败包装成 `run.completed`。
- 同步修改数据库完整 SQL、迁移器、CU 策略提示词、网络重试配置和键盘降级策略。
- 匿名边界实测：首页、社区、帖子详情、带 `user_id` 的公开主页返回 200；我的主页和发布页跳转登录；匿名消息和写请求返回 401。
- 所有 PHP 入口移除通配 CORS；恶意 Origin 不返回 ACAO，同源 Origin 正确返回。
- 认证日志已对 Authorization、API Key、Token、Cookie 和 PHP Auth 字段脱敏。
- Windows 发布不再携带历史日志、上传数据、下载数据和测试目录。
