# MoonYa Work 子代理与动态办公室开发约定

## 源码与运行组合

真实子代理仅在 Work 模式启用。使用 deepseek-harness-master 的五个子代理包，共 34 个核心源码文件；Foundation 副本只更换包名前缀。scripts/build-subagent-runtime.mjs 核对上游文件并生成实际发布的运行时及来源哈希，许可证保留在根目录 THIRD_PARTY_NOTICES.md。

foundation-host.mjs 挂载原有 Cordis Agent、Session、进程内 Spawn、驱动、派发和控制工具；MoonYa 适配层连接模型配置、现有工具、审批、截图、压缩及历史。保持 subagent、send_message、interrupt_agent，后台可继续协作，最多 MoonYa → 子代理 → 下级子代理，maxDepth=2。任务与外观没有能力绑定，同一轮可派出多个任意任务。

## 并发与结算

默认每用户 8 个执行名额，跨 Work 会话共享，主代理不计入。并发设置接受正整数并持久保存；增加立即调度排队任务，降低等待已运行任务释放名额。等待下级或审批时释放名额，恢复执行重新排队，避免嵌套任务占满名额后死锁。

父代理消费原有持久化结算通知，并在相关子任务全部结算后给出最终汇总。分支停止先关闭整条分支准入，再取消运行和排队的所有下级，等待资源释放后记录已取消。关闭事实持久化，迟到事件不得恢复被取消的分支。运行时重启恢复持久事实并标记中断；读取办公室不得唤醒代理或重复执行未知副作用。

## 办公室投影与界面

初始只有 MoonYa，真实创建后增加人物和工位，按创建顺序排列，MoonYa 固定首位。保留人物、桌椅、显示器和背景风格，动态换行并可滚动。人物素材按顺序循环，派发可指定 avatar，素材可重复使用；不预放置固定员工，不按职业限制任务。

目录使用原始 subagent/catalog，生命周期持久化为 subagent/start/end。office/agent-state 记录排队和等待，office/appearance 单独记录外观和完整任务，不修改上游目录格式。投影键为 (Work 会话 ID, child ID)，保存首次创建的 created_turn 和 created_seq，按持久序号重放并去重，乱序时补齐目录和外观。目录不进入模型消息，也不能依靠模型正文推断员工状态。

名称使用任务说明，空白回退为“子代理 N”。显示排队、运行、等待、完成、失败和已取消；点击查看任务、父子关系、执行记录、结果并停止整个分支。完成、失败、取消后仍保留，切换会话只切换展示；刷新和返回从持久事实恢复。清空或删除（含批量删除）会话取消任务并释放投影。

主界面和独立窗口订阅同一会话；PHP 网关统一检查登录用户、会话和工作目录归属，子代理事件保持身份，审批通过根事件转发，但子代理正文和终止事件不能终止主代理流。

## Work 对话中的子代理行

每个真实目录员工独立占一行，位置为用户消息 → 用时过程区 → 子代理行 → MoonYa 回复。使用统一线条 SVG、任务描述和六种状态，不使用人物素材；原生按钮支持鼠标、回车和空格，默认收起，长标题省略但状态与箭头保留。下级同样单独一行，父子关系在展开详情显示。成功派发摘要由该行展示，失败工具记录及右侧原始日志保留。

subagent-store.js 是办公室和对话的共享会话事实源；办公室隐藏不影响对话订阅。subagent-chat.js 按 created_turn 定位原始轮次，保存 renderer-neutral 身份与轮次，恢复默认收起，再以快照校准。旧对话不迁移；读取与恢复不得启动执行。清空、删除、切换会话和退出页面须关闭对应记录订阅并隔离缓存。

展开详情读取原始派发 prompt，使用现有 Markdown 和工具详情渲染。office_employee_events 网关接收 session_id、project_path、child_id、after_seq，也支持 children JSON 游标表将多个展开记录复用一条连接。所有 child ID 必须属于该根会话目录；转发 subagent_event 保留根、子会话身份与子会话序号，只更新对应行，禁止转为主回复 content/done。收起关闭该员工订阅，再展开从缓存序号续传；重连按子会话去重、按序重放。记录流排除内部历史、检查点及原始截图数据。

## 验证与发布

必须覆盖 12 个任务/8 个执行名额、任意任务与重复外观、嵌套及越级拒绝、等待释放名额、失败隔离、整分支取消及迟到事件、跨会话与用户隔离、审批、刷新恢复和重连去重。前端交互需检查超过 9 人的布局、详情、并发输入和独立窗口。

对话交互还须检查 12 行与原始轮次、独立展开及键盘操作、完整长任务、Markdown 结果、实时工具记录、全部状态、主回复终态隔离、详情断线续传及清空删除。全部展开仍须为其他请求保留浏览器连接。

源码相关测试和 MoonYa 测试通过后检查 Windows 构建、发布目录哈希及单文件运行时实际派发。安装包必须含生成的真实子代理代码、持久化 worker、Koffi 以及目标架构原生依赖。只通过静态文件检查不足以证明 exe 能运行。
