> **版本**: v1.0

> **状态**: 待评审

## 一、核心约束（严格执行）

| # | 约束 | 实施方案 |
|---|------|---------|
| 1 | **禁止使用 Python 后端** | 基于 **PuppeteerSharp**（.NET 8，Playwright 的 .NET 移植版）直接在 WPF 项目中控制浏览器 |
| 2 | **不依赖 Computer Use 的任何组件** | Browser Automation 完全独立于 `AIAssistant.php`、`ComputerUseService.cs`、`UiAutomationService.cs`，不调用它们的任何方法，不复用任何降级逻辑 |
| 3 | **截浏览器窗口，不截桌面** | PuppeteerSharp 的 `Page.ScreenshotAsync()` 仅截取浏览器视口（viewport），不涉及 `Graphics.CopyFromScreen` |
| 4 | **严禁任何硬编码提示词** | 所有 Agent 提示词、工具调用提示词、VLS 分析提示词全部存入 `system_prompts` 和 `tool_settings` 表，通过管理后台编辑 |
| 5 | **仅在 Work 模式和 Computer User 模式下可用** | 前端 `agent_mode='agent'`（Work 模式）或 `computer_user_mode=true` 时，后端才注入 BA 工具声明和对应提示词 |
| 6 | **严格禁止任何应变/降级** | 浏览器操作失败直接返回错误给用户，不降级到坐标点击、不降级到键盘快捷键，不调用任何 CU 回退机制 |

## 三、详细交互流程

### 3.1 完整流程

```
步骤 0: 用户触发
  用户: "帮我打开百度搜索 MoonYa AI"
  当前模式: Work 模式 (agent_mode='agent') 或 CU 模式
     ↓

步骤 1: 安全授权
  BrowserSecurityGate 弹出授权窗口 (WPF 原生模态窗):
  ┌──────────────────────────────────────────────┐
  │  MoonYa 浏览器自动化 - 安全确认               │
  │                                              │
  │  即将访问: baidu.com                          │
  │  即将执行的操作:                              │
  │  1. 导航到 baidu.com                         │
  │  2. 在搜索框输入 "MoonYa AI"                 │
  │  3. 点击搜索按钮                             │
  │                                              │
  │  [✓ 允许本次操作]  [✓ 信任 baidu.com]        │
  │  [✗ 拒绝]                                    │
  └──────────────────────────────────────────────┘
     ↓  (用户确认)

步骤 2: 启动浏览器会话
  BrowserAutomationService:
  → PuppeteerSharp 启动有头 Chromium（用户可见浏览器窗口）
  → Navigate → baidu.com
  → ScreenshotAsync() → 仅截浏览器视口
  → 通过 SSE 推送 ba_screenshot 事件到前端
  → 前端展示首帧截图
     ↓

步骤 3: 调用 VLS-Agent 进行视觉分析
  PHP 后端接收截图 base64
  → 从 system_prompts 加载 browser_vls_agent 提示词
  → 调用视觉模型（moonshot-v1-8k-vision-preview 等）
  → 视觉模型分析浏览器截图中的页面布局
  → 返回结构化分析结果

  VLS-Agent 输出（通过 SSE 推送 vls_analysis 事件）:
  ┌──────────────────────────────────────────────┐
  │  VLS-Agent 视觉分析报告                        │
  │                                              │
  │  页面: 百度首页                               │
  │  检测到 2 个可交互元素:                        │
  │                                              │
  │  1. 搜索输入框                                │
  │     • CSS: #kw                                │
  │     • 位置: (320, 280, 520, 320)              │
  │     • 状态: 空, 可输入                         │
  │                                              │
  │  2. 搜索按钮                                 │
  │     • CSS: #su                                │
  │     • 位置: (580, 280, 680, 320)              │
  │     • 文本: "百度一下"                        │
  │                                              │
  │  ⏳ 分析完成，我将交给 MoonYa Agent            │
  └──────────────────────────────────────────────┘
     ↓

步骤 4: MoonYa Agent 接管执行
  MoonYa Agent 根据 VLS 分析结果调用 BA 工具:
  → browser_click(selector="#kw")
  → browser_fill(selector="#kw", text="MoonYa AI")
  → browser_click(selector="#su")
  → 每步自动截图并 SSE 推送
  → 操作完成后汇总截图展示给用户
     ↓

步骤 5: 用户查看结果
  前端展示所有操作步骤的缩略图列表
  用户可点击放大查看每一步的截图
  用户可继续下发指令或结束会话
```

### 3.2 失败处理（禁止降级）

```
操作失败 → 直接返回错误信息给用户:
  { "success": false, "error": "元素 #kw 未找到，页面可能未完全加载" }

  不允许的行为:
  ❌ 不得尝试坐标点击回退
  ❌ 不得切换到键盘快捷键策略
  ❌ 不得调用 CU 工具兜底
  ❌ 不得自动重试超过 1 次

  用户可:
  - 重新调用 VLS-Agent 重新分析当前页面
  - 手动调整后再次尝试
  - 放弃操作
```

#### browser_automation 提示词模板

```
你是 MoonYa 的浏览器自动化助手 (Browser Automation Agent)。
你可以通过以下工具操控浏览器：

【浏览器操控工具】
- browser_navigate(url): 导航到指定 URL
- browser_click(selector): 点击指定 CSS 选择器的元素
- browser_fill(selector, text): 在输入框中填入文本
- browser_screenshot(): 截取当前浏览器页面（仅浏览器视口）
- browser_scroll(direction, amount): 滚动页面
- browser_get_text(selector): 获取元素文本
- browser_wait(ms): 等待指定毫秒
- browser_evaluate(js_code): 在浏览器中执行 JavaScript

【工作模式】
- VLS 模式：先调用 browser_screenshot → VLS-Agent 分析 → 根据分析结果操作
- 直接操作模式：直接用浏览器工具，不需要 VLS 分析

【操作规则】
1. 每次操作后自动截图返回
2. 元素不存在时直接报错，不重试
3. 指定超时（默认 10 秒），超时直接返回错误
4. 任务完成后必须调用 task_complete
```

#### browser_vls_agent 提示词模板

```
你是 MoonYa 的 VLS-Agent (Vision Language Service Agent)，专门用于分析浏览器页面。

你收到的图片是浏览器页面的截图（仅浏览器视口，不含桌面）。

你需要输出以下结构化分析：
1. page_summary: 页面整体描述
2. elements: 可交互元素列表（类型、CSS 选择器、位置、状态）
3. suggested_next_action: 推荐的下一步操作

输出格式为 JSON 包裹在 ```vls 代码块中。
分析完成后，必须在末尾说"分析完成，我将交给 MoonYa Agent"。
```

### 5.1 BrowserAutomationService.cs 核心 API

| HTTP 端点 | 方法 | 参数 | 说明 |
|-----------|------|------|------|
| `/browser/start` | POST | `{url}` | 启动浏览器并导航到 URL |
| `/browser/navigate` | POST | `{url}` | 导航到新 URL |
| `/browser/click` | POST | `{selector}` | 点击元素（CSS Selector） |
| `/browser/fill` | POST | `{selector, text}` | 输入文本 |
| `/browser/screenshot` | GET | - | 截取浏览器视口截图（返回 base64） |
| `/browser/scroll` | POST | `{direction, amount}` | 滚动页面 |
| `/browser/get-text` | POST | `{selector}` | 获取元素文本 |
| `/browser/evaluate` | POST | `{js_code}` | 执行 JS |
| `/browser/wait` | POST | `{ms}` | 等待 |
| `/browser/stop` | POST | - | 关闭浏览器 |
| `/browser/status` | GET | - | 获取浏览器运行状态 |

**截图流程（关键差异点）**：

```csharp
// 使用 PuppeteerSharp 截图，仅截浏览器视口
var screenshotBytes = await page.ScreenshotAsync(new ScreenshotOptions
{
    Type = ScreenshotType.Png,
    FullPage = false  // 仅视口，非全页
});
var base64 = Convert.ToBase64String(screenshotBytes);
```

## 十一、PuppeteerSharp 技术选型依据

| 对比项 | PuppeteerSharp | Python Playwright | CefSharp 内嵌浏览器 |
|--------|---------------|------------------|-------------------|
| 运行层 | .NET 8 原生 | ❌ 违反"禁止 Python"约束 | .NET 8 原生 |
| 截图范围 | 仅浏览器视口 | - | 可截，但受 WPF 窗口布局影响 |
| 元素定位 | CSS/XPath/Text | - | 需通过 JS 桥接 |
| 独立进程 | ✅ 独立 Chromium 进程 | - | ❌ 嵌入在 WPF 窗口内 |
| NuGet 包 | `PuppeteerSharp` | - | 已有 CefSharp |
| 自动下载 Chromium | ✅ 支持 | - | - |

选择 **PuppeteerSharp** 的核心原因：
1. 纯 .NET 实现，不依赖 Python
2. 独立进程运行浏览器，截图不受桌面布局影响
3. 提供完整的 DOM 元素定位 API（CSS Selector、XPath）
4. 截图仅包含浏览器视口内容（`FullPage = false`），符合需求
5. 与现有 C# launcher 架构一致，可通过 HTTP API 通信
