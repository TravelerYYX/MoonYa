# 支付宝电脑网站支付部署与验收

支持手动购买一个月、续费、升级、降档排队、用户订单查询与后台查单。不包含自动续费、代扣或在线退款。当前默认关闭购买；真实支付宝收款须在商户资料准备完成后另行验证。

## 已确认的会员规则

- 免费用户首次购买：付款确认后开始一个月，只发所购套餐积分，结束免费剩余额度。
- 同套餐续费和降档：按服务器付款确认顺序加入队列，当前套餐及前面已购套餐结束后生效；开始时发整月积分，不提前发分、不结转旧周期余额。
- 升级：全价购买，新余额为原剩余积分加新套餐整月积分，确认付款当天重新起算一个月，原剩余天数作废。
- 升级不删除已付款队列。队列随后按原购买顺序生效，可能回到原档位。后台人工切档／改到期时间也保留并顺延队列，调整积分不改日期。
- 采用北京时间、自然月周年日、月底截断。连续排队月份共享日期锚点，例如 1 月 31 日、2 月 29 日、3 月 31 日，不永久改到 29 日。
- 等级与价格、积分、显示排序独立：免费 0，GO 1，Plus 2，Pro 3，Max 4。已有订阅和订单保存等级快照。已有自定义套餐未设置等级时不可购买；管理员设置等级后，缺失等级的当前订阅只补充等级，不改变原积分快照。
- 升级积分转移通过 `credit_transfers` 记录；升级前启动的模型调用沿转移链结算，最多扣至转入余额和目标余额的较小值。普通到期或人工切档的调用仍结算原周期。离线跨多期只初始化实际当前周期，不补发过期积分。

## 商户与密钥准备

1. 在支付宝开放平台准备已签约“电脑网站支付”的应用，确认 AppID 与收款商户 UID（16 位，通常以 2088 开头）。不要把 AppID 当商户 UID。
2. 选择 RSA2 公钥模式或公钥证书模式。应用私钥必须保留在服务器，支付宝公钥用于验签；证书模式还需要应用公钥证书、支付宝公钥证书和支付宝根证书。
3. 私钥、公钥使用可被 OpenSSL 读取的 PEM 文件；私钥不加密码。保存于站点根目录之外，例如 `/etc/moonya/alipay/`，限制权限，使 PHP 进程可读、公众不可读。证书同样放在站点根目录之外。
4. 粘贴进后台的材料必须是**带装甲的 PEM**（含 `-----BEGIN/END ...-----` 头尾行）。开放平台与密钥工具界面上复制到的是**裸 base64**，OpenSSL 读不了，会统一报「需要至少 2048 位的有效 RSA 密钥」——该文案同时覆盖「解析失败」「非 RSA」「位数不足」三种情况，容易误判成密钥太短。补齐装甲（两种输入方式任选）：
   - 剪贴板：材料复制后 `php 检测脚本/alipay_key_check.php --armor private --clip`，结果直接写回剪贴板（`public` 同理）。
   - 文件：`php 检测脚本/alipay_key_check.php --armor private 私钥.base64.txt > 私钥.pem`。
   保存前先用 `php 检测脚本/alipay_key_check.php 私钥.pem private`（`public` 同理）确认输出「通过，可以保存」。
   **注意**：`--armor` 生成的私钥头是 `PRIVATE KEY`（PKCS#8），公钥头是 `PUBLIC KEY`（SPKI）；文件名带 `.pem` 不代表内容是 PEM，务必用上面的脚本验一次。
5. 密钥材料目录（如仓库内的 `密钥/`）已在 `.gitignore` 挡住（`**/密钥/`、`**/*.base64.txt`），但**更推荐放在仓库之外**（例如 `C:\MoonYaPaymentKeys\`），避免误提交。
6. 准备支付宝可访问的公网 HTTPS 后端地址。`ALIPAY_PUBLIC_URL` 是后端根地址（可带部署子路径），不含查询参数，不能指向桌面回环服务。

支付配置现由后台“支付配置”页面管理，整个配置与密钥材料使用 AES-256-GCM 加密保存。主密钥由数据库键环保管；保存、导入和结清订单均只验证当前管理员密码，无需邮箱验证码或 SMTP。首次可一次性导入原 `.env` 配置，运行期间不会回退 `.env`。

上线前必须完成支付安全迁移、数据库键环初始化与 HTTPS 配置；导入和结清订单还需管理员邮箱及 SMTP 配置。具体命令、根证书信任、主密钥轮换与恢复见 [支付安全部署说明](PAYMENT_SECURITY.zh.md)。

支付开关关闭不阻止已付款通知和查单。未结清订单会阻止更换商户、环境或密钥；支付配置页提供复验后的查单与关单入口。初次导入必须与未结清订单的商户和环境一致。

## 发布与迁移顺序

1. 备份代码、数据库和服务端配置。按现有流程发布 PHP 后端，不复制开发机 `.env` 或任何支付材料。
2. 在 `MoonYa-Backend` 执行 `composer install --no-dev --prefer-dist --optimize-autoloader`；使用提交的 `composer.lock`。需要 PHP 8.1+、64 位整数、PDO MySQL、cURL、OpenSSL，测试还需要 DOM。
3. 若会员基础表尚未建立，先完成原会员部署。已有会员表只需执行 `php sql/migrate_payments.php`。支付迁移新增三张表及独立等级，不重置余额、不覆盖价格、不重复开通；可重复执行。
4. 在管理后台“会员套餐”给自定义套餐设置唯一等级。初始已知套餐自动补等级；未知套餐不按价格或积分猜测。保留购买开关关闭。
5. 构建并发布前端和更新桌面网关；先完成前端构建，再执行运行时打包验证，避免竞争 `dist`。
6. 配置商户材料，打开后台“会员订单”检查开关、环境、迁移和缺少的配置项。配置未完整时购买按钮不可用，但会员查询、积分账本和模型计费照常工作。
7. 设置每分钟运行的服务器任务：`php /服务器路径/MoonYa-Backend/sql/reconcile_payments.php 100`。该命令只补查待确认及本地超时订单，不执行退款；失败返回非零退出码。配置错误时明确报错，不会尝试向任意地址发送请求。
8. 验证公网异步通知地址 `https://后端根地址/api/alipay.php?action=notify` 可接收支付宝 POST，不要求用户登录、不重定向到登录页。只在验签、核验和数据库提交成功后返回纯文本 `success`，否则返回 `failure`，让支付宝重试。
9. 在商户配置和签约确认后在后台通过管理员密码复验启用购买，完成真实小额付款验收，再开放购买。当前本地开发验收不代表已验证真实收款。

`tools/build_server_bundle.py` 排除环境文件和常见密钥／证书扩展名；支付材料必须另外存放。不要直接公开整个仓库或忽略站点对 `Services`、`vendor`、`sql`、环境文件的访问限制。

## 接口与恢复行为

- `GET api/membership.php`：当前账户、目录、待生效队列、购买可用状态、Cookie 会话的 CSRF 令牌。原 `action=ledger` 保留。
- `GET ...?action=orders&page=1`：本人订单，每页 20 条；`action=order&order_no=...`：本人订单详情。
- `POST ...?action=create_order`：`plan_id`、16–80 字符的 `request_key`；同一请求重试返回同一订单。一个用户同时只有一个待付款订单，默认期限 30 分钟。
- `POST ...?action=resume_order`／`sync_order`：`order_no`，分别继续付款和主动查单。Cookie 会话 POST 必须带 `X-CSRF-Token`；桌面 Bearer 请求使用既有网关鉴权。
- `POST ...?action=delete_order`：`order_no`，仅本人未付款且无权益记录的订单可删除，沿用上述 CSRF／桌面鉴权。返回 `{order_no, deleted: true}`，重复删除成功。存在支付宝交易时先查单、关单并确认；交易不存在时立即隐藏并作废站内付款链接。后台记录及补查保留，晚到真实付款正常发放权益并恢复个人列表显示。订单返回 `can_delete` 控制删除入口。
- `GET api/alipay.php?action=checkout&token=...`：仅限随机短期支付凭据，不携带用户登录令牌；付款或到期后失效。该页禁止缓存并设置不发送 Referrer。
- `GET ...?action=return`：先验签并核对订单、AppID、商户及金额，再读取已确认订单或向支付宝主动查单。付款确认后显示“付款成功”，通过 `moonya://payment/return?order_no=订单号` 自动打开 MoonYa；客户端已运行时恢复现有窗口，打开订单页并自动更新会员信息。未确认时自动重查，最多六次；浏览器阻止自动打开时可点击“打开 MoonYa”。返回参数本身不授权发放会员。
- `admin/api/membership_orders.php`：GET 支持页码、付款状态、用户 ID、完整订单号筛选和详情；POST 主动查单，需要 `edit_users` 权限，操作写入管理员日志。不返回私钥、支付凭据或上游原始响应。

公网查单只使用官方 SDK 验签后的响应。异步通知还核对 AppID、商户、订单号、金额、交易号。官方 SDK 的查单响应模型不包含 `seller_id`，查单由冻结商户配置对应的应用私钥发起，收银台明确指定订单商户；不能用前端返回的商户信息补充查单结果。

成功页需要同时发布 `api/alipay.php`、`Services/PaymentService.php`、`Services/PaymentReturnPage.php`，以及包含最新 `frontend/` 的 Windows 客户端。安装程序注册 `moonya` 协议，便携客户端首次正常启动时为当前用户注册协议。尚未安装或启动过新版客户端的电脑不能完成应用唤起。

付款和权益状态独立：订单 `pending/paid/expired/closed`，权益 `queued/active/expired/replaced`。本地超时不等于确认未付款，超时订单也允许补查；真实成功付款不会因为本地超时被丢弃。第一次服务器成功确认的时间作为即时套餐起点，支付宝付款时间独立记录。

付款确认在用户行锁内串行判断当时套餐和队列，再原子更新订单、权益及流水。创建订单后发生人工切档或其他已付款权益变化时，以确认付款时的实际当前套餐判断立即生效或排队。页面显示队列的预计日期，日期可随后续升级／人工调整顺延。

遇到网络错误，先查询原订单，不要重复下单。同一次购买失败重试复用请求标识；明确过期的原请求不能复活，可重新选择套餐创建新请求。付款弹窗提供“继续付款”打开外部浏览器、“我已完成支付”查询服务器结果；关闭页面、退出登录或换账号后停止付款轮询。

用户删除功能上线前，先执行 `php MoonYa-Backend/sql/migrate_payments.php`，为现有订单表新增 `user_deleted_at` 字段；该迁移可重复运行，不改变余额和已购权益，再发布新版后端及前端。
